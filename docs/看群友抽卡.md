# Watchice 抽卡规则

## 1. 基本规则

- 抽卡范围为当前用户**可以查看的所有 active 图片**。
- 图片是否进入卡池完全由现有 Watchice 权限系统决定，不额外维护卡池权限。
- 所有图片**等概率抽取**。
- 抽卡采用**有放回抽样**，同一张图片可以在一次十连中重复出现。
- 第一版仅支持：
  - 单抽：1 张
  - 十连：10 张
- 当前没有任何可见图片时，拒绝抽卡，不扣除 Data，也不创建抽卡记录。

## 2. 抽卡价格

暂定价格：

- 单抽：256KB
- 十连：2MB

价格以后可能调整，因此当前价格属于配置，不写死为历史规则。

每次实际抽卡时，仍需要在抽卡记录中保存当次真实消耗的 Data，避免以后修改价格后影响历史记录。

Data 必须始终完整保存为：

- `base`
- `addition`
- `zero`

三个字段共同构成一个完整 Data 状态，不能省略 `zero`。

## 3. 抽卡配置

抽卡价格、是否启用等少量配置建议放在轻量 JSON 文件中，例如：

```json
{
  "enabled": true,
  "single_cost": {
    "base": 10,
    "addition": 8,
    "zero": false
  },
  "ten_cost": {
    "base": 20,
    "addition": 1,
    "zero": false
  }
}
```

配置文件体积很小，可以在抽卡时直接读取，使修改后无需重启即可生效。

## 4. 图片表

现有 `images` 表不增加抽卡专用字段。

不添加：

- `collectible`
- `rarity`
- `draw_weight`

原因：

- 不人为划分图片稀有度。
- 不同群友之间的所谓“稀有”没有统一比较标准。
- 卡池范围直接使用现有图片权限模型。
- 所有可见图片统一等概率抽取。

## 5. 用户持卡

新增 `user_cards` 表。

字段：

```text
user_id
image_id
owned_count
first_obtained_at
```

主键：

```text
PRIMARY KEY(user_id,image_id)
```

规则：

- 第一次抽到图片时创建记录，`owned_count=1`。
- 重复抽到时直接增加 `owned_count`。
- 不创建单独的“卡片实例”。

### 权限变化

用户已经获得的卡不会因为图片权限变化而删除。

例如：

```text
曾经可见并抽到
→ 后来图片变为不可见
→ user_cards 记录仍然保留
```

但收藏页只展示用户**当前仍有权限查看**的图片。

如果以后权限重新开放，该卡重新显示，并保留之前的 `owned_count`。

因此：

> 所有权是历史事实，可见性是当前权限。

## 6. 抽卡记录

新增 `gacha_draws` 表。

字段：

```text
draw_id
user_id
request_id
count
cost_base
cost_addition
cost_zero
created_at
```

其中：

- `draw_id`：一次抽卡操作的唯一 ID。
- `user_id`：抽卡用户。
- `request_id`：请求唯一 ID，用于防止重复抽卡。
- `count`：本次抽卡数量，目前仅允许 1 或 10。
- `cost_*`：本次实际消耗的完整 Data。
- `created_at`：抽卡时间。

约束：

```text
UNIQUE(user_id,request_id)
```

同一个用户使用相同 `request_id` 重试时：

- 参数相同：返回第一次抽卡结果，不重新扣 Data、不重新抽卡。
- 参数不同：视为请求冲突。

## 7. 单次抽卡结果

新增 `gacha_draw_items` 表。

字段：

```text
draw_id
position
image_id
is_new
copies_after
```

主键：

```text
PRIMARY KEY(draw_id,position)
```

字段含义：

- `draw_id`：属于哪次抽卡。
- `position`：本次抽卡中的第几抽。
- `image_id`：抽到的图片。
- `is_new`：这一抽是否为用户第一次获得该图片。
- `copies_after`：这一抽结算完成后，用户拥有该图片的数量。

例如用户第一次在十连第 2 抽获得图片 755，又在第 7 抽重复获得：

```text
position=2
image_id=755
is_new=true
copies_after=1

position=7
image_id=755
is_new=false
copies_after=2
```

`copies_after` 保存的是当时的历史快照，与当前 `user_cards.owned_count` 不同。

## 8. 收藏范围

收藏范围动态计算：

```text
total_collectible
= 当前用户可见的 active 图片数量
```

```text
owned_unique
= 当前可见图片中用户已经拥有的不同图片数量
```

因此不同用户由于权限不同，收藏总数可以不同。

图库新增、删除或权限变化后，收藏总数也允许动态变化。

## 9. 暂不实现

第一版暂不实现：

- 稀有度
- 卡牌权重
- 保底
- 无放回十连
- 集齐奖励
- 卡片实例
- `data_before`
- `data_after`

集齐奖励暂时取消，主要原因是：

- 当前 Data 本身已经很多，抽卡主要用于消耗 Data。
- 卡池范围会随图片和权限动态变化，“集齐”状态并不稳定。
- 暂时没有必要再建立一套奖励领取状态。

## 10. 当前第一版目标

第一版抽卡系统最终应支持：

```text
当前用户权限
→ 计算当前可见 active 图片池
→ 等概率、有放回抽取 1 或 10 次
→ 扣除 Data
→ 写入抽卡历史
→ 更新 user_cards
→ 返回每一抽的 is_new / copies_after
```

核心原则：

> 图片权限就是卡池权限。

> 所有可见图片等概率。

> 历史记录保留过去发生的事实，收藏展示遵循当前权限。
